# Research 多市场多周期扩展计划

这份文档用于明确 `research-2` 后续从“BTC 单一周线页”扩展到“多市场、多币种、多周期研究页”的实施顺序、页面编排和验收口径。

当前目标不是一次性把所有功能同时做完，而是用最少返工的顺序，先把框架搭对，再逐步补数据、扩周期、接抓取、接回测。

## 1. 当前现状

当前 `research-2` 的核心限制是：

- 页面当前基本固定为 `BTC + 周线`
- 数据层当前仍偏硬编码，核心路径是 `BTCUSD_PERP`
- 页面结构还没有抽象成 `市场 × 币种 × 周期`
- 周线、日线、3日线还没有统一的数据接口和页面切换框架

这意味着：

- 如果现在直接补大量数据，后面页面切市场、切周期时还会返工
- 如果现在直接做日线和 3 日线，后面数据源和缓存结构也会返工

所以当前最优策略不是“先大量补数据”，而是“先重构框架，再补数据”。

## 2. 总目标

后续研究页需要支持三维切换：

- 市场：`币本位 COIN-M` / `U本位 USDT-M`
- 币种：当前支持研究的交易对
- 周期：`周线` / `3日线` / `日线`

阶段性目标如下：

1. 先完成周线版本的多市场、多币种框架
2. 再扩到 3 日线和日线
3. 再做定时抓取、质量校验、taskboard 接入
4. 最后做多周期统一回测

## 3. 推荐优先级

推荐按下面顺序推进：

### 阶段 1：先抽统一数据模型

先把研究页数据层改造成统一接口，支持：

- `market_type`
- `symbol`
- `timeframe`

这一阶段先只落地周线，不急着同时做日线和 3 日线。

原因：

- 这是后面所有扩展的基础
- 如果不先统一，后面页面和脚本都会重复写多套逻辑

### 阶段 2：先重构页面框架

在页面上先加入：

- 市场切换
- 币种切换
- 周期切换占位

这一阶段只要求周线能切市场和币种，不要求日线与 3 日线马上可用。

### 阶段 3：补齐周线数据

在框架稳定后，再补：

- COIN-M 全部币本位币种的周线历史
- USDT-M 同名单币种的周线历史

原因：

- 页面和接口稳定后，数据进来就能直接复用
- 不会先导入大量数据再改结构

### 阶段 4：确认周线版本

周线稳定后，再做：

- 布局确认
- 切换体验确认
- URL 参数与缓存确认
- 数据一致性确认

确认没问题后，再进入下个阶段。

### 阶段 5：扩到 3 日线和日线

复用阶段 1 和阶段 2 已经搭好的统一框架。

这一步不要重新造一套页面，而是共用同一套研究页壳层。

### 阶段 6：定时抓取、质量校验、taskboard

等多市场、多周期版本稳定后，再做：

- 抓取时间设计
- 抓取准确性校验
- 异常补抓与重跑策略
- taskboard 面板接入

### 阶段 7：统一回测框架

最后基于：

- 日线
- 3 日线
- 周线

建立统一回测方法，为后续量化做准备。

## 4. 页面编排建议

页面不要做成“顶部一排全是切换按钮”的平铺结构。推荐做成三级分层。

### 第一层：市场切换

放在最上面，作为一级标签：

- `币本位 COIN-M`
- `U本位 USDT-M`

这是全局最高优先级切换。

### 第二层：周期切换

放在市场切换下方，作为二级标签：

- `周线`
- `3日线`
- `日线`

当前阶段先只开放 `周线`，另外两个可以先显示为灰态或 `即将开放`。

### 第三层：币种切换

币种切换不要和市场、周期同级。建议放成：

- 一排常用币快捷标签：`BTC / ETH / BNB / SOL / XRP ...`
- 一个搜索/下拉选择器用于更多币种

原因：

- 币种数量会越来越多
- 币种维度属于对象维度，不适合和全局维度混在同一层

## 5. 页面布局建议

推荐布局从上到下如下：

1. 页面标题区
   - 标题：`研究页`
   - 当前上下文：`COIN-M / 周线 / BTC`

2. 一级切换：市场

3. 二级切换：周期

4. 币种选择区
   - 热门币快捷切换
   - 搜索选择器

5. 概览 KPI 区
   - 当前状态
   - 最新数据日期
   - 平均区间长度
   - 数据源说明

6. 参数设置区
   - 分段参数
   - 指标参数

7. 主图与联动图区
   - 价格 + 七态背景
   - funding
   - RSI
   - ADX / BBW / Return Z
   - volume
   - 时间截断控件

8. 统计与画像区
   - 七态区间统计
   - 阈值解释
   - 家族汇总

## 6. 数据范围建议

### 周线阶段

先做：

- COIN-M：全部币本位币种
- USDT-M：只做和 COIN-M 同名单币种

这个范围控制是合理的，原因是：

- 先保证两市场可横向对照
- 避免 U 本位全量币种过多，导致数据和页面都失控

### 3 日线与日线阶段

也建议先沿用同一名单，不要立即放大到所有 USDT-M 币种。

## 7. 数据模型建议

研究页底层建议统一成以下三维：

- `market_type`: `coinm` / `usdtm`
- `symbol`
- `timeframe`: `1w` / `3d` / `1d`

后续无论是：

- 研究页查询
- 缓存键
- 回测脚本
- 数据源说明
- taskboard 任务说明

都统一围绕这三维展开。

## 8. 阶段性验收标准

### 阶段 1 验收

- 数据接口可以接收 `market + symbol + timeframe`
- 周线研究数据不再写死 `BTCUSD_PERP`
- 缓存键已纳入市场、币种、周期维度

### 阶段 2 验收

- 页面可切换 `COIN-M / USDT-M`
- 页面可切换不同币种
- 周期切换 UI 已经预留
- 不破坏当前 BTC 周线逻辑

### 阶段 3 验收

- COIN-M 周线历史补齐
- USDT-M 同名单周线历史补齐
- 页面切换各币种时能正常出图

### 阶段 4 验收

- 页面布局合理
- 切换不卡顿
- 数据日期和数据源说明准确
- 参数与图层联动正常

### 阶段 5 验收

- 3 日线页可用
- 日线页可用
- 页面框架不新增重复实现

### 阶段 6 验收

- 定时抓取时间确定
- 完整性校验落地
- 异常任务可定位
- taskboard 上能看到状态

### 阶段 7 验收

- 日 / 3 日 / 周 三周期回测口径统一
- 方法文档稳定
- 可作为后续量化实验基础

## 9. 当前正式执行顺序

当前建议正式按下面顺序开始做：

1. 先重构 `research-2` 的统一数据模型
2. 再重构 `research-2` 页面框架
3. 再补多市场周线数据
4. 页面确认后，再扩 3 日线和日线
5. 最后接抓取、质检、taskboard、回测

## 10. 当前不建议做的事

当前不建议：

- 直接先补全部 USDT-M 币种
- 直接同时做周线、3日线、日线三套页面
- 在页面结构未稳定前先接 taskboard
- 在样本不足时先投入精细量化回测

## 11. 下一步

下一步建议直接进入：

- `阶段 1：重构 research-2 的统一数据模型`

也就是先把当前 `BTC + 周线 + 单市场` 的硬编码数据接口抽象掉，为后面的多市场、多币种、多周期扩展做底座。
